# Grox Discord Bot

## Огляд

Багатофункціональний Discord‑бот, написаний на Python 3 з використанням **discord.py 2.x** (slash‑команди).  
Бот підтримує:

* Привітання нових учасників  
* Модерацію (ban, unban, kick, mute, warn, warnings)  
* Захист від спаму та масових згадок  
* Систему XP/рівнів із випадковим отриманням XP за повідомлення  
* Тікет‑систему (створення, закриття, історія)  
* Інформаційні команди (`/help`, `/ping`, `/serverinfo`, `/userinfo`, `/stats`)  
* Health‑endpoint (`/`) для моніторингу

Усі повідомлення – українською. Дані зберігаються у PostgreSQL через **asyncpg**.

## Структура репозиторію

```
grox-projects/
└─ discord-bot/
   ├─ main.py            # головний файл, містить весь функціонал
   ├─ requirements.txt
   ├─ README.md
   └─ .env.example
```

> У цьому репозиторії весь код розміщений у `main.py` задля простоти запуску.

## Встановлення

1. **Клонувати репозиторій**

   ```bash
   git clone https://github.com/your-org/grox-projects.git
   cd grox-projects/discord-bot
   ```

2. **Створити файл `.env`**  
   Скопіюйте `.env.example` та заповніть реальними значеннями:

   ```bash
   cp .env.example .env
   ```

   Параметри:

   | Змінна                | Опис                                    |
   |-----------------------|------------------------------------------|
   | `DISCORD_TOKEN`       | Токен вашого Discord‑бота                |
   | `DATABASE_URL`        | DSN PostgreSQL (`postgresql://user:pass@host/db`) |
   | `WELCOME_CHANNEL_ID`  | ID каналу, куди надсилати привітання    |
   | `SUPPORT_ROLE_ID`     | ID ролі підтримки (для тікетів)          |
   | `ARCHIVE_CATEGORY_ID` | ID категорії, куди переміщати закриті тікети |
   | `PORT` (необов’язково) | Порт для health‑endpoint (за замовчуванням 8080) |

3. **Встановити залежності**

   ```bash
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. **Ініціалізувати базу даних**  
   При першому запуску `main.py` автоматично створить потрібні таблиці.

5. **Запуск бота**

   ```bash
   python main.py
   ```

   Після успішного підключення ви побачите в консолі повідомлення про готовність бота.  
   Health‑endpoint буде доступний за адресою `http://localhost:<PORT>/` і повертатиме JSON:

   ```json
   {"status":"ok","discord_ready":true}
   ```

6. **Запуск тестів** (необов’язково, тестовий пакет не включений у цьому мінімальному шаблоні)

   ```bash
   pytest
   ```

## Основні команди (українською)

| Команда | Опис |
|---------|------|
| `/help` | Список усіх команд |
| `/ping` | Перевірка затримки |
| `/serverinfo` | Інформація про сервер |
| `/userinfo [користувач]` | Інформація про користувача |
| `/stats` | Статистика бота (кількість серверів, користувачів, відкритих тікетів) |
| `/rank [користувач]` | Ваш XP та рівень |
| `/leaderboard` | Топ‑10 користувачів за XP |
| `/ticket open` – створює приватний канал для підтримки |
| `/ticket close` – закриває поточний тікет і переміщує його в архів |
| `/ticket history` – історія ваших тікетів |
| `/ban`, `/unban`, `/kick`, `/mute`, `/warn`, `/warnings` | Модераційні дії (потрібні відповідні права) |

## Додаткова інформація

* **Anti‑spam**: більше 5 повідомлень за 5 секунд → тайм‑аут 10 хв. Масові згадки (`@everyone`, `@here`) автоматично видаляються.
* **XP**: кожне повідомлення (яке не вважається спамом) дає 5‑15 випадкових XP. Підвищення рівня за формулою `5*level² + 50*level + 100`.
* **Тікети**: створюються у вигляді окремих текстових каналів, доступних лише користувачу та ролі підтримки. При закритті канал переміщується в категорію архіву.
* **Health‑endpoint**: корисний для Docker/Kubernetes моніторингу. Повертає `discord_ready: true` лише після успішного підключення до Discord‑Gateway.
